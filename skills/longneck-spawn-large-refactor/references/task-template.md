# 大規模リファクタのタスク文書テンプレート

`longneck-spawn-large-refactor` が作成する4文書のテンプレートである。
形式の正本は `../../longneck/references/task-format.md` であり、ここでは用途別の内容だけを定める。
`<...>` は作成時に確定した値で置き換える。
値がインラインコードで終わる場合は、値と、値に続く日本語の間に半角スペースを入れる。
`description.md` は100行および8 KiB以内に収める。
ピン止めとリファクタの方針の記述が長く、この大きさに収まらない場合は、ユーザーが指定した内容を省かずに記録することを優先する。
この場合にCLIの `validate` が報告する大きさのwarningは、結果の報告でそのまま伝える。

## 目次

- `description.md`
- `state.md`
- `progress.md`
- `issues.md`

## `description.md`

```markdown
# <title> — タスク定義

概要: <リファクタ対象の短い説明>を、ピン止めされた挙動を保ったまま、設計から見直して作り直す。

## 目的

<リファクタ対象の短い説明>が抱える設計上の問題を、ピン止めされた領域の挙動を変えない範囲で、根本原因から解決する。

## スコープ

- リファクタ対象: <ユーザーが指定した対象>
- 現状のレビュー, 問題の整理, 解決案と設計の作成, 設計に従った実装, 実装の検証
- ピン止めされた挙動を固定する特性テストの作成（作成できる範囲に限る）
- リファクタ後の設計を記述する恒久的な文書の作成と、内容が古くなる既存の文書の更新
- リファクタ対象の変更に伴って必要になる、対象の外の変更（設計に明記したものに限る）

## 非スコープ

- ピン止めされた領域の挙動の変更（ピン止めされた領域で観測できるバグの修正を含む）
- リファクタ対象の外にある既存の問題の修正
- ブランチの作成と切替え, リモートへのpush, PRの作成などの外部への操作（ユーザーが明示的に指示した場合を除く）
- <ユーザーが対象外として指定したもの。なければこの行を省く>

## 完了条件

次のいずれかを満たす。

- 最新の検証サイクルの対応で、修正が必要な指摘が0件である。
- 問題の整理で、解決の対象とする問題が0件である。
- 検証の継続確認で、ユーザーが打ち切りを選んだ。

## 長期制約

- 各タスクは、Longneckスキル群の `longneck-spawn-large-refactor/references/refactor-protocol.md`（`longneck-head` スキルからの相対パスは `../longneck-spawn-large-refactor/references/refactor-protocol.md`）に従う。親は同文書の「親の規則」に従う。
- ピン止め（リファクタによって挙動を変更してはならない領域）:
  - <ユーザーが指定したピン止め。1つの領域を1行に書く>
- ピン止めの解釈:
  - <作成時にユーザーへ確認して確定した解釈。なければ「確認した事項なし」>
- リファクタの方針: <ユーザーが指定した方針、または方針を定める文書のパス。指定がなければ「指定なし」>
- 旧実装の参照先: <「基準コミット `<コミットID>`」、またはユーザーが指定した旧実装の複製のパス>
- スナップショットの `設計の承認` が `承認済み` になるまで、`.longneck` の外にあるファイルを変更しない。
- 解決案と設計は、ユーザーが承認するまで次の段階へ進めない。
- 調査, 設計, 検証を担当する子のモデル: <モデル名。指定がなければ「指定なし（タスク項目に `- モデル:` 行を置かない）」>
- 実装を担当する子のモデル: <モデル名。指定がなければ「指定なし（タスク項目に `- モデル:` 行を置かない）」>
- 継続確認の間隔: <サイクル数。既定は3>サイクル
- コミット方針: <「コミットしない」または「タスクごとにコミットする」のうち、作成時に確定したもの>

## 主な作業対象

- `<リファクタ対象の主なパス>`
```

`永続化対象外` のセクションは、`longneck-spawn` の定めに従い、ユーザーが宣言を明示的に求めた場合だけ、`主な作業対象` の後に置く。

## `state.md`

`- モデル:` 行は、調査, 設計, 検証を担当する子のモデルが指定された場合だけ置く。
`確認なしで開始できる最終検証サイクル` の初期値は、継続確認の間隔と同じ番号にする（間隔が3なら `003`）。

```markdown
# <title> — 現在の状態

更新日時: <RFC3339>
状態: active

## 現在のスナップショット

- 現在の段階: 現状調査
- 解決案の承認: 未承認
- 設計の承認: 未承認
- 現在の検証サイクル: なし
- 確認なしで開始できる最終検証サイクル: <NNN>
- 終了理由: 未終了

## 調査待ち

### T-0001 — 現状調査

- 目的: リファクタ対象の構成, 外部との接点, 実行と検証の方法, 特性テストの実現性を調べ、現状レビューの範囲を分割して、`docs/overview.md` へ保存する。
- 完了条件: `docs/overview.md` が保存され、レビュー範囲ごとの「現状レビュー」のタスクと「問題の整理」のタスクが追加されている。
- 依存関係: なし
- 規約: Longneckスキル群の `longneck-spawn-large-refactor/references/refactor-protocol.md` の「基本方針」, 「共通規則」, 「現状調査」に従う。
- モデル: <調査, 設計, 検証に指定されたモデル>

## 判断待ち

なし。

## 実行待ち

なし。

## ブロック中

なし。
```

## `progress.md`

```markdown
# <title> — 進捗

## 設計判断

なし。

## 作業ログ

### <RFC3339> — 管理作業

- 実施: 大規模リファクタのタスクを作成した。
- 検証: 作成前に、リファクタ対象が存在すること, 対象に未コミットの変更がないこと, titleが既存のtitleと衝突しないことを確認した。
```

旧実装の参照先が、ユーザーが指定した旧実装の複製のパスである場合は、
`検証` の行の「対象に未コミットの変更がないこと」を「旧実装の複製が存在すること」に替える。

## `issues.md`

`task-format.md` のテンプレートをそのまま使い、`未解決` は `なし。` とする。
