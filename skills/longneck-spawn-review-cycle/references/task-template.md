# レビューサイクルのタスク文書テンプレート

`longneck-spawn-review-cycle` が作成する4文書のテンプレートである。
形式の正本は `../../longneck/references/task-format.md` であり、ここでは用途別の内容だけを定める。
`<...>` は作成時に確定した値で置き換える。
値がインラインコードで終わる場合は、値と、値に続く日本語の間に半角スペースを入れる。
`description.md` は100行および8 KiB以内に収める。
`対象の特定方法` へ記録する一覧が長く、この大きさに収まらない場合は、対象を再現可能に列挙することを優先する。
この場合にCLIの `validate` が報告する大きさのwarningは、結果の報告でそのまま伝える。

## 目次

- `description.md`
- `state.md`
- `progress.md`
- `issues.md`

## `description.md`

```markdown
# <title> — タスク定義

概要: <レビュー対象の短い説明>のレビューと修正を、指摘がなくなるまで繰り返す。

## 目的

<レビュー対象の短い説明>について、レビュー, 修正案の作成, 修正のサイクルを繰り返し、レビューの指摘がない状態にする。

## スコープ

- レビュー対象: <ユーザーが指定した対象>
- 対象の特定方法: <対象を再現可能に列挙する方法。基準コミットやコマンド、またはファイルの一覧>
- サイクルの修正による変更（`state.md` のスナップショットにある `修正による変更` の一覧）も、レビュー対象に含める。
- レビューの指摘に対する修正の実施

## 非スコープ

- レビュー対象の範囲外にある既存の問題の修正
- リモートへのpush, PRへのコメント投稿などの外部への操作（ユーザーが明示的に指示した場合を除く）
- <作成時の作業ツリーにあった、レビュー対象に含めない変更。なければこの行を省く>

## 完了条件

次のいずれかを満たす。

- 最新のサイクルのレビューで、指摘が0件である。
- 最新のサイクルの修正案で、修正項目が0件である。
- 継続確認で、ユーザーが打ち切りを選んだ。
- 修正項目を1件も実施できなかった修正のタスクの問いへ、ユーザーが修正を見送ると回答した。

## 長期制約

- 各タスクは、Longneckスキル群の `longneck-spawn-review-cycle/references/cycle-protocol.md`（`longneck-head` スキルからの相対パスは `../longneck-spawn-review-cycle/references/cycle-protocol.md`）に従う。親は同文書の「親の規則」に従う。
- レビューの担当には、過去のサイクルのレビュー結果, 修正案, 台帳, それらの要約を渡さない。
- `state.md` のスナップショットと `progress.md` には、指摘, 修正方針, ユーザー判断の内容を書かない。
- レビュー観点: <ユーザーが指定した観点。指定がなければ「指定なし（規約の既定に従う）」>
- レビューと修正案を担当する子のモデル: <モデル名。指定がなければ「指定なし（タスク項目に `- モデル:` 行を置かない）」>
- 修正を担当する子のモデル: <モデル名。指定がなければ「指定なし（タスク項目に `- モデル:` 行を置かない）」>
- 継続確認の間隔: <サイクル数。既定は5>サイクル
- コミット方針: <「コミットしない」または「修正のタスクごとにコミットする」のうち、作成時に確定したもの>

## 主な作業対象

- `<レビュー対象の主なパス>`

## 永続化対象外

- `docs/` にあるレビュー結果, 修正案, 台帳
- `state.md` と `progress.md` にある、サイクルの進行状況, 残タスク, 作業履歴, ユーザー判断の経緯
- このタスク定義の目的, スコープ, 非スコープ, 完了条件, 長期制約, 主な作業対象
```

`永続化対象外` のセクションは、`SKILL.md` の手順でユーザーが宣言に同意した場合だけ含める。
同意しなかった場合は、見出しを含めてセクションごと省く。
省いた場合は、`task-format.md` の定めにより、すべての知見が永続化の対象になる。

セクションを含めた場合も、`issues.md` の内容は永続化対象外に含めない。
そのため、レビュー対象の範囲外で見つかった問題の記録は、タスクの削除時に通常どおり永続化の対象になる。

## `state.md`

`- モデル:` 行は、レビューと修正案を担当する子のモデルが指定された場合だけ置く。
`確認なしで開始できる最終サイクル` の初期値は、継続確認の間隔と同じ番号にする（間隔が5なら `005`）。

```markdown
# <title> — 現在の状態

更新日時: <RFC3339>
状態: active

## 現在のスナップショット

- 現在のサイクル: 001
- 現在の段階: レビュー
- 確認なしで開始できる最終サイクル: <NNN>
- 修正による変更: なし
- 指摘件数: なし
- 終了理由: 未終了

## 調査待ち

なし。

## 判断待ち

なし。

## 実行待ち

### T-0001 — サイクル001: レビュー

- 目的: レビュー対象を、過去のサイクルを知らない状態でレビューし、結果を `docs/cycle-001-review.md` へ保存する。
- 完了条件: レビュー結果が保存され、指摘が1件以上あれば「サイクル001: 修正案」のタスクが追加されている。
- 依存関係: なし
- 規約: Longneckスキル群の `longneck-spawn-review-cycle/references/cycle-protocol.md` の「共通規則」と「レビュー」に従う。`progress.md` と `docs/` を開く前に、同文書の「レビュー」の「前提」を読む。
- モデル: <レビューと修正案に指定されたモデル>

## ブロック中

なし。
```

## `progress.md`

```markdown
# <title> — 進捗

## 設計判断

なし。

## 作業ログ

### <RFC3339> — 管理作業

- 実施: レビューサイクルのタスクを作成した。
- 検証: 作成前に、レビュー対象が空でないことと、titleが既存のtitleと衝突しないことを確認した。
```

## `issues.md`

`task-format.md` のテンプレートをそのまま使い、`未解決` は `なし。` とする。
