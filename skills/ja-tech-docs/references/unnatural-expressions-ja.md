# AI が使いがちな不自然な日本語表現

生成された日本語技術文書やコードコメントで繰り返し観測された、避けるべき表現の一覧である。
いずれも「意味はなんとなく分かるが、日本語の技術文書では使わない」か「読者が意味を確定できない」もの。
[style-ja.md](style-ja.md) の「独自表現を作らない」「語句の関係を明示する」
「気取った文体を使わない」の具体例として使う。

レビューでは、この一覧に該当する語を低〜中重要度の指摘として扱い、言い換え先を示す。
ただし「6. 気取った文体」は、含意が読者の操作や判断を誤らせる場合は高重要度、それ以外は中重要度として扱う。
一覧にない語でも、同じ分類に当てはまる表現は同様に避ける。

## 1. 別の意味の動詞を転用したもの

日常語や別分野の動詞を、データの変換や伝播の意味に転用した表現。
読者は元の語義から意味を推測することになり、確信を持てない。

| 避ける表現 | 転用された意味 | 言い換え |
|---|---|---|
| 写る, 写す (「500 に写る」「Location に写す」) | ある値や失敗が、別の値や応答に変換される | 「500 応答になる」「500 として返す」「Location にそのまま設定する」「〜に変換する」 |
| 束（「ports の束」） | 同列概念のグループ、リスト | 「ports 群」「ports 一覧」「すべての ports」 |
| 束ねる, 束ね (「文脈を束ねる」) | 複数のものをまとめる、情報を付加する | 「まとめる」「付与する」「関連付ける」 |
| 丸める, 丸め (「区別を 1 つに丸める」) | 複数の区別を 1 つに潰す、単一の値として扱う | 「集約する」「〜として扱う」「置き換える」。数値の丸め (丸め誤差, 整数へ丸める) は標準用語なのでそのまま使う |
| 落とす, 落ちる (「未特定に落とす」「400 に落とす」) | 失敗や既定値へ遷移させる | 「〜として扱う」「〜を返す」「〜にする」「～としてまとめる」 |
| 剥がす (「prefix を剥がす」) | 文字列や層を取り除く | 「取り除く」「除去する」 |
| 素通しする | 検査や変換をせずにそのまま渡す | 「そのまま渡す」「変換せずに中継する」 |

## 2. 造語の名詞

英語の概念を漢語に直訳したり、既存の語を組み合わせて作った、定着していない名詞。

| 避ける表現 | 意図した意味 | 言い換え |
|---|---|---|
| 公開入口 | モジュールが外部に公開するファイルや API | 「公開インターフェース」「エントリポイント」「公開 API」。ファイルを指すなら `index.ts` のように識別子で書く |
| 核 (「モジュールの核」) | 中心となるロジック | 「中核」「コアロジック」「本体」 |
| 受け口 (「通知の受け口」) | 要求を受け付けるエンドポイントや関数 | 「受信エンドポイント」「受け付ける関数」 |
| 印 (「エラー応答の印」) | 状態を示すフラグ | 「フラグ」「目印となるフィールド」 |
| 電文 | 送受信されるメッセージ | 「メッセージ」「リクエスト」「応答」「送受信データ」 |

## 3. 意味を確定できない限定語, 強調語

読者が「何と対比しているのか」を判断できない語。
書き手だけが知る比較対象を前提にしている。

| 避ける表現 | 問題 | 言い換え |
|---|---|---|
| ちょうど 400 (「ちょうど 400 も失敗として扱う」) | 「4xx 全般でなく 400 のみ」なのか「400 を境界として含む」なのか分からない | 「400 も失敗として扱う」「ステータスが 200〜299 の範囲外はすべて失敗として扱う」のように条件を明示する |
| 意図的差分, 意図的な拡張 | 何との差分かが書かれていない | 差分の説明をやめて現在の挙動を仕様として書く、またはこのような記述自体を行わない |
| 他版と逆, 〜と同じ判断 | 比較先を知らない読者には意味がない | 比較をやめて現在の場所の挙動だけを書く、またはこのような記述自体を行わない |

## 4. 定着していないカタカナ転写と直訳

| 避ける表現 | 言い換え |
|---|---|
| ワイヤ, ワイヤ形式, ワイヤ化 | 「送受信データ形式」「JSON の形式」「シリアライズ」「エンコード」 |
| パーシストする | 「永続化する」「保存する」 |
| 病的ケース, 病的パス | 定訳がないため原語のまま「pathological case」と書く |

## 5. 英語の名詞句を助詞に直結したもの

[style-ja.md](style-ja.md) の「書き換えの例」を参照する。

- 悪い例: connection pool の exhaustion 時にリトライする
- 良い例: 接続プールが枯渇したときに再試行する

## 6. 気取った文体

事実を指す定着した語があるのに、比喩, 擬人化, 誇張, 英語の慣用句の直訳へ言い換えた表現。
規則と判定基準は [style-ja.md](style-ja.md) の「気取った文体を使わない」にある。
読者に元の事実への復元を強いるうえ、比喩の連想が事実にない含意を持ち込む。
「事実にない含意」の列には、その表現を読んだ読者が事実として受け取りかねない内容を示す。

| 避ける表現 | 事実にない含意 | 言い換え |
|---|---|---|
| 回す価値のあるダイアル, レバー, つまみ | 値を連続的かつ安全に何度でも変えられる | 「変更する価値のあるパラメータ」「効果の大きい設定項目」 |
| 存在意義を証明する, 真価を発揮する, 本領を発揮する | 以前は疑われていた、または特定の場面でだけ有効である | 「重要である」「有効である」「〜の場合に効果が大きい」 |
| 生き残る, 生き延びる (「この設計は生き残った」) | 淘汰や競争を経た | 「現在も使われている」「維持されている」 |
| 心臓部, 屋台骨, 生命線 | それが止まると全体が止まる | 「中核」「基盤」。全体が止まることが事実なら、その条件と結果を書く |
| 門番, 番人 (「型検査が門番になる」) | 悪意ある侵入を想定している | 「〜を検証する」「〜を拒否する」 |
| 地雷, 罠, 足を撃つ | 意図的に仕掛けられている | 「誤用しやすい」「〜すると失敗する」「不具合」 |
| 舞台裏, ボンネットの下, 裏側 | 意図的に隠されている | 「内部では」「実装では」 |
| 重労働を担う, 重い処理を肩代わりする | 負荷が高い | 「主な処理を行う」「〜の大部分を処理する」 |
| 低い所にある果実, 手の届く果実 | 残りの項目は困難である | 「少ない変更で対応できる項目」 |
| 旅, 物語, 道のり (「リクエストの旅」) | 長く困難である | 「処理の流れ」「手順」 |
| 魔法, 魔法のように | 仕組みを説明できない | 仕組みを書く。「自動で〜する」 |
| 悲鳴を上げる, 火を噴く, 息切れする | 突発的で制御できない | 「負荷が上限に達する」「応答時間が〜を超える」「失敗する」 |
| まさに, 見事に, 劇的に, 驚くほど, 〜と言っても過言ではない | 程度が客観的に大きい | 根拠のある量や条件を書く。根拠がなければ削る |
